# Domain docs

This repository uses one root `GLOSSARY.md` and stores architecture decision records in `docs/adr/`.

Before exploring the codebase, read the glossary and any ADRs relevant to the work. If either is absent, proceed. Add terms and decisions as they are agreed.

Use glossary terms in tickets, design proposals, and tests. If a proposal conflicts with an ADR, name the ADR and explain why the decision should be revisited.
